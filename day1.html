    반복 업무 자동화 1일차

    홈쇼핑·이커머스 실무자를 위한 워크플로 자동화 — 편성표·매출·리포트·메일을 매주 돌려받기

    3 : 7
    손으로 만들며 익힘
    ✋

    코딩 경험은 필요 없습니다. 오늘 끝에는 "스케줄 → 구글시트 → 메일"이 자동으로 도는 첫 워크플로를 직접 만들어 실행합니다.

    이틀 동안 코딩 없이 내 업무를 자동화하는 법을 함께 만든다고 오프닝. 매주 반복하는 업무(편성표·매출·주간 리포트·CS) 하나를 떠올리게 하고, 끝나면 하나는 무조건 켜서 간다는 효능감을 준다.
    ⏰ 왜 자동화인가

    매주 손으로 만드는 그 리포트,
    코딩 0줄로 자동화할 수 있다면?

    홈쇼핑 실무의 반복 업무는 패턴이 분명합니다 — 패턴이 분명하면 자동화 후보입니다.

    • 📅매일 아침 오늘 방송 편성표를 시트에서 확인해 담당자에게 메일
    • 📊매일·매주 매출 시트를 열어 상품군별로 합산하고 요약을 작성
    • 📧주간 성과 리포트를 만들어 팀장·메일링리스트에 발송
    • 💬CS 문의를 읽고 배송/환불/상품문의로 분류·요약

    오늘의 중심 목표: 이 반복 업무들을 만드는 부품(트리거·노드·분기·다중출력·디버깅)을 1일차에 쌓고, 2일차에 주간 성과 리포트로 조립합니다.

    "이 반복 업무를 코딩 0줄로 자동화할 수 있다면?"이 오늘의 질문. "코딩 0줄" 문구에 잠깐 머무르고, 가능하면 완성형 주간 리포트를 1초 보여 "이틀 뒤 결과물"로 각인. 일부는 "자동화=코딩이라 나랑 무관"이라 여기니 "오늘 코드 한 줄도 안 칩니다"를 명시.

    🧑‍💻 M1 · 반복 업무 자동화 이해하기

    "AI 업무 자동화 전문가" =
    반복 프로세스를 발견하고 워크플로로 설계하는 사람

    도구를 아는 사람이 아니라, 내 업무에서 자동화할 곳을 찾아 설계·구축·유지보수하는 사람입니다.

    🔍
    ① 프로세스 분석
    내 업무 중 반복되고 규칙이 분명한 작업을 찾아낸다.
    ✏️
    ② 자동화 설계
    트리거→액션 흐름과 조건·데이터 처리를 그림으로 설계한다.
    🔨
    ③ 구축
    n8n에서 노드를 연결해 실제 동작하는 워크플로로 만든다.
    🔧
    ④ 유지보수
    에러 핸들링·로그 확인으로 실패에 대비하고 고친다.
    "AI 업무 자동화 전문가"는 반복 프로세스를 발견→설계→구축→유지보수하는 사람. 오늘 연습하는 것이 정확히 이것이라고 연결.
    ⚖️ M1 · 분류 활동

    자동화하기 좋은 일 vs 어려운 일

    자동화는 "반복 + 규칙이 명확"할 때 빛납니다. 매번 다른 판단이 필요하면 어려운 일입니다.

    ✅
    자동화 좋은 일
    • 매일/매주 반복되는 작업
    • 규칙이 분명(언제·무엇을·어디로)
    • 데이터 기반: 편성표 읽기 → 메일, 매출 집계 → 리포트
    • 사람 손이 단순 옮기기/집계인 작업
    ⚠️
    자동화 어려운 일
    • 매번 다른 판단·협상·창작
    • 규칙이 모호하거나 예외가 대부분
    • 사람의 감각/맥락이 핵심인 일
    • 입력이 정형화되지 않은 일
    💡

    팁: "규칙이 분명한 자연어 분류"(예: CS 문의를 배송/환불로 나누기)는 AI 노드로 자동화 가능 — 2일차에 직접 다룹니다.

    자동화하기 좋은 일=규칙이 분명하고 반복되는 일(매일 9시 편성표 메일), 어려운 일=매번 사람 판단이 달라지는 일(클레임 보상 여부). 업무를 불러주고 손들기로 분류 활동(시간 절약). 밀리면 분류를 3개로 줄인다.
    ⚠️ M1 · 흔한 오개념 교정

    시작 전에 내려놓을 3가지 오해

    ❌

    "자동화 = 코딩이라 나는 못 한다" → n8n은 노드를 화면에서 연결하는 방식. 오늘 코딩 0줄로 첫 워크플로를 만듭니다.

    ❌

    "한 번 만들면 끝이다" → 데이터·계정·정책은 바뀝니다. 에러 핸들링과 로그 확인이 필수(M6에서 연습).

    ❌

    "툴이 알아서 다 해준다" → 무엇을 언제 시작하고(트리거) 어디로 보낼지(매핑)는 내가 설계해야 합니다. 엑셀 매크로와도 다릅니다.

    "n8n으로 자동화하려면 결국 코딩을 할 줄 알아야 한다."

    거짓. n8n은 노드를 화면에서 드래그·연결하는 방식이라 코딩 0줄로 첫 워크플로를 만들 수 있습니다. (값을 꺼내는 {{ }} 표현식만 약간 익히면 됩니다.)
    내려놓을 오해 3가지: ①자동화=코딩이라 어렵다(오늘 코드 안 침) ②한 번 만들면 끝(에러처리·유지보수 필요→디버깅 배움) ③엑셀 매크로와 같다(n8n은 시트뿐 아니라 메일·외부 서비스·AI까지 묶음).
    🔑 M1 · 도구 지도 — 오늘의 가장 중요한 구분

    Claude 구독 ≠ Anthropic API 키
    같은 'Claude'지만 용도가 다릅니다

    💬
    Claude 구독 (claude.ai 챗)
    claude.ai 챗. 회사가 제공.
    용도: 설계·디버깅 보조 — 워크플로 아이디어, 표현식 작성, 에러 로그 해석.
    워크플로 안의 AI 노드는 구동 못 함.
    🔌
    Anthropic API 키
    console.anthropic.com 발급. 회사 제공 확정.
    용도: n8n 워크플로 안의 AI 노드(Anthropic Chat Model 등)를 실제로 실행.
    2일차에 여러분이 직접 핸즈온합니다.
    🚫

    가장 자주 깨지는 가정: "Claude 구독이 있으니 워크플로에서 그대로 쓰면 되겠지" → 아니요. n8n의 Anthropic 노드는 API 키로만 동작합니다. (출처: n8n 공식 커뮤니티 + Anthropic 헬프센터)

    n8n 워크플로 안의 AI 노드(Anthropic 노드)를 실제로 구동하려면 무엇이 필요할까요?

    정답: B. 워크플로 안의 Anthropic 노드는 API 키로만 동작합니다. claude.ai 챗 구독은 설계·디버깅 보조용일 뿐 워크플로 AI 노드는 구동하지 못합니다.
    오늘 가장 중요한 슬라이드 — 절대 빨리 넘기지 말고 두 번 반복. 개인 Claude 구독(claude.ai 챗=설계·디버깅 보조)과 Anthropic API 키(워크플로 안에서 Claude 실행)는 완전히 다르다. 구독이 있어도 워크플로 안 Claude 노드는 그냥 안 돌아간다(가장 자주 깨지는 가정). 질문 "구독으로 워크플로 Claude가 바로 돌까?"에 다수가 "된다"로 오답 → "안 됩니다"로 정정.
    📦 M2 · n8n 기초

    n8n = 노드를 연결해 만드는
    워크플로 자동화 도구

    서비스(구글시트·Gmail·Claude…)들을 노드로 놓고 선으로 이어, "이런 일이 생기면 → 이걸 한다"를 흐름으로 그립니다.

    핵심 비유 🧩 — n8n 워크플로는 컨베이어 벨트입니다. 트리거가 벨트를 켜고, 데이터(아이템)가 노드를 하나씩 거치며 가공되어, 마지막 액션에서 시트·메일로 나갑니다.

    • 🖱️코딩 없이 노드를 드래그·연결로 구성 (표현식만 약간)
    • ☁️이 강의 실습 환경 = n8n Cloud(매니지드). 가입하면 바로 시작
    n8n은 노드를 연결해 만드는 워크플로 자동화 도구. 블록(노드)을 선으로 이으면 자동화 흐름이 된다 — 레고 조립에 비유.
    🧱 M2 · 워크플로의 4가지 구조

    이 4개 단어만 알면 워크플로를 읽을 수 있습니다

    • 트
      트리거 (Trigger) — 흐름을 시작시키는 사건.예: 매일 09:00에 실행(Schedule Trigger), 외부 호출 수신(WebhookWebhook — 외부 서비스가 특정 사건이 생겼을 때 미리 약속한 URL로 데이터를 "밀어 보내" 워크플로를 즉시 시작시키는 방식입니다.). "언제 켜지나 = 트리거"
    • 액
      액션 (Action) — 실제로 일을 수행하는 노드.예: 구글시트에 행 추가, Gmail로 메일 발송.
    • 노
      노드 (Node) — 하나의 블록. 트리거도 액션도 모두 노드.노드 하나 = 한 가지 일. 노드들을 선으로 이으면 워크플로.
    • 분
      조건분기 (Branch) — 조건에 따라 갈라짐.예: 매출이 목표 미달이면 이쪽, 아니면 저쪽(IF 노드). M4에서 본격 학습.

    "매일 09:00에 워크플로를 자동으로 시작"하는 것은 무엇에 해당하나요?

    정답: A. 정해진 시각에 흐름을 시작시키는 것은 트리거(Schedule Trigger)입니다. 메일 발송·시트 쓰기처럼 일을 수행하는 것이 액션입니다.
    흐름을 읽는 네 단어: 트리거(흐름을 시작시키는 사건, 매일 9시), 액션(실제 일 수행, 메일·시트 쓰기), 노드(블록 하나), 조건분기(길을 가르기). 신규 개념 4개가 인지부하 상한이라 더 얹지 않는다.
    ⏻ M2 · 트리거 & 액션 — 시작과 실행

    트리거가 흐름을 켜고
    액션이 실제 일을 합니다

    워크플로의 두 기둥 — 무엇이 흐름을 시작시키는가(트리거), 그리고 무엇이 실제 일을 수행하는가(액션).

    ⏻
    트리거 — 흐름을 시작시키는 사건
    "언제 켜지나"를 정한다.
    • Schedule Trigger — 매일 09:00에 실행
    • Webhook — 외부 호출이 오면 즉시 실행
    ⚡
    액션 — 실제 일을 수행하는 노드
    "무엇을 하나"를 수행한다.
    • Google Sheets — 편성표 읽기 / 행 추가
    • Gmail — 담당자에게 메일 발송
    📅

    홈쇼핑 예시: "매일 09:00에(트리거) 편성표 시트를 읽어(액션) 담당자에게 메일을 보낸다(액션)" — 트리거 1개가 켜면 액션들이 차례로 일합니다.

    트리거=언제 시작하나, 액션=무엇을 하나. 트리거가 스케줄이면 정해진 시각, 웹훅이면 외부 신호 시 시작. 트리거 하나에 액션 여러 개가 줄줄이 붙는다. S9의 확장이라 빠르게 짚는다.
    📦 M2 · 노드 & 워크플로 — 블록과 연결

    노드는 블록,
    이은 전체가 워크플로입니다

    노드 하나가 한 가지 일을 하고, 노드들을 선으로 이으면 하나의 자동화(워크플로)가 됩니다 — 코딩 0줄.

    • 노
      노드 (Node) — 하나의 블록. 트리거도 액션도 모두 노드.노드 하나 = 한 가지 일(시트 읽기, 메일 보내기 …).
    • 워
      워크플로 (Workflow) — 노드들을 선으로 연결한 전체 자동화.트리거에서 시작해 액션들로 데이터가 흐릅니다.
    • 분
      조건분기 (Branch) — 흐름의 갈림길(IF).조건에 따라 다른 길로 보냅니다. M4에서 본격 학습.
    🖱️

    캔버스에서 드래그·연결, 코딩 0줄: 노드를 화면에 끌어다 놓고 선으로 이으면 끝. 값을 꺼내는 {{ }} 표현식만 약간 익히면 됩니다.

    노드=일 하나를 맡는 부품 블록, 워크플로=블록들을 선으로 이은 완성품. 캔버스에서 블록을 놓고 잇는 게 곧 워크플로를 짓는 것. S9 확장이라 빠르게.
    ☁️ M2 · 실습 환경 둘러보기

    🍴 M4 · 헷갈리는 두 노드

    IF와 Filter는 무엇이 다른가

    🔀
    IF — 두 갈래
    true / false 두 출력이 생긴다. 양쪽을 각각 다르게 후속 처리할 때.
    예: 미달 방송은 요약 시트에, 달성 방송은 그냥 통과.
    🧹
    Filter — 거르기
    통과 아이템만 남기고 나머지는 버린다(분기 없음).
    예: 빈 행·목표 달성 행을 빼고 미달 행만 다음으로.
    ⚠️

    흔한 실수: 매출이 "1,200,000" 처럼 문자열이면 숫자 비교가 항상 실패합니다 → 콤마 제거 후 Number로 변환해 비교하세요.

    "통과할 아이템만 남기고 나머지는 버리되, 분기는 만들지 않는다" — 어느 노드일까요?

    정답: B. Filter는 통과 아이템만 남기고 나머지는 버립니다(분기 없음). IF는 true/false 두 출력으로 갈라 양쪽을 각각 다르게 처리할 때 씁니다.

    체크포인트 · M4 조건분기

    위 IF vs Filter 문항을 먼저 풀고 눌러 보세요.

    아직 부족해요. M4 조건분기 첫 슬라이드로 돌아가기 ↑
    IF=두 갈래(참이면 true 경로, 거짓이면 false 경로, 양쪽 다 따로 처리). Filter=한 갈래(통과한 것만 남기고 나머지 버림). 둘 다 처리하면 IF, 남길 것만이면 Filter. 캔버스에서 IF의 두 출력과 Filter의 단일 출력을 나란히 비교. true/false 가지를 거꾸로 연결하는 실수 잦음.
    🔢 M4 · 조건식의 함정 — 문자열 vs 숫자

    매출이 "1,200,000"이면
    숫자 비교가 항상 실패합니다

    콤마가 들어간 문자열("1,200,000")은 숫자(1200000)와 다릅니다. IF가 "작다/크다"를 따질 수 없어 비교가 늘 어긋납니다.

    ⚠️
    증상
    매출 시트의 일일매출_콤마 열이 "1,200,000"(콤마 문자열).
    IF 매출 < 목표매출 가 항상 false — 미달 방송이 하나도 안 잡힌다.
    🔧
    해결
    ① 콤마 제거 → ② Number로 변환 후 비교.
    ③ IF 조건의 데이터 타입을 Number로 지정.
    ⚠️

    시연: 일일매출_콤마 열을 그대로 비교 → 미달 0건. 콤마 제거·Number 변환·조건 타입 Number로 바꾸면 정상적으로 미달 방송만 분기됩니다.

    가장 많이 막히는 건 타입 불일치 — 매출이 "1,200,000"처럼 콤마 든 문자열이면 숫자 비교가 어긋난다. 콤마 빼고 Number로 변환 후 비교. 비교 연산자도 데이터 타입에 맞게. 타입 함정 1회 시연.

    조건을 AND로 묶어
    대상을 더 좁힙니다

    조건은 하나가 아니어도 됩니다. 여러 조건을 AND로 결합하면 둘 다 맞는 아이템만 true 가지로 갑니다.

    ✔️

    습관: 분기 후 true / false 가지 라벨을 꼭 확인하세요. 가지를 거꾸로 연결하면 의도와 반대로 처리됩니다.

    조건 두 개 이상 묶기: IF 노드 안에서 조건 추가 후 AND로 묶으면 둘 다 참일 때만 true, OR는 하나만 참이어도 통과. 오늘은 AND만 한 번. Lab2: 매출 < 목표매출 IF로 걸어 true 가지에 미달 방송만 흐르게.

    Σ M5 · 집계의 개념 — group + sum

    상품군을 키로 묶어
    매출을 합산합니다

    집계 = "같은 상품군끼리 모아서(group) 매출을 더한다(sum)". 다중발송으로 가기 전, 먼저 하나의 요약을 만드는 단계입니다.

    Σ
    Summarize 노드 설정
    • fieldsToSplitBy = 상품군 (묶는 키)
    • sum = 매출 (합산할 값)
    → 출력 키 sum_매출 생성.
    🧮
    결과 예시
    입력: 주방 120 · 주방 80 · 패션 200
    → [{상품군:주방, 합계:200}, {상품군:패션, 합계:200}]
    상품군별 하나의 요약 아이템.
    ⚠️

    함정: 집계 전에 발송하면 행마다 메일이 따로 갑니다. 반드시 먼저 집계해 하나의 요약을 만든 뒤 발송하세요.

    집계=여러 행을 하나로 묶어 요약. 핵심은 무엇으로 묶고(group) 무엇을 더하나(sum) — 상품군으로 묶고 매출 더하면 행이 상품군 수만큼 줄어든다. n8n은 Summarize 노드가 group+sum 담당. 집계하면 데이터가 줄어든다는 감만 잡으면 됨(다음 발송 단계 전제). group+sum으로 행이 줄어드는 걸 전/후 행 수 비교로 1회 시연.
    🧱 M5 · Lab3 단계

    일일 매출 → 상품군별 합산 → 여러 곳 발송

    • 1
      Sheets · Get Row(s) — 일일 매출 읽기(방송명·상품군·매출).
    • 2
      상품군별 합산 — Edit Fields(Set)/집계로 group(상품군) + sum(매출).결과 예: [{상품군:주방, 합계:200}, {상품군:패션, 합계:200}] — 하나의 요약 아이템.
    • 3
      Sheets · Append — 요약 시트에 집계 결과 기록({{ $json.상품군 }}·{{ $json.합계 }} 매핑).

      Gmail · Send ×2 이상 — 같은 요약을 담당자 + 팀 메일링리스트로. 필요하면 Merge로 분기 결과를 합쳐 한 번에.
    🎯

    성공 기준: 같은 집계 결과가 요약 시트 + 메일(2곳 이상)에 동일하게 정확히 출력되면 다중출력 완성.

    순서: 먼저 집계, 그다음 발송. 집계 안 하고 바로 메일 보내면 행 100개=메일 100통 폭탄 → 반드시 하나의 요약 아이템으로 묶은 뒤 발송. Lab3: 매출 읽기→상품군별 합산→요약 시트 Append→메일 발송(2곳 이상). "집계 먼저"를 일부러 틀리게 보여주고 고치는 시연이 효과적.
    🛡️ M6 · 1일차 정리 · 디버깅

    실패하면? 에러 핸들링과 실행 로그

    "한 번 만들면 끝"이 아닙니다. 워크플로가 깨질 때 어디서·왜를 찾는 도구를 익힙니다.

    🚨
    Error Trigger
    워크플로가 실패하면 자동으로 실행되는 별도 흐름. 실패를 잡아 알림 등을 보낼 수 있다.
    ⛔
    Stop And Error
    특정 조건에서 일부러 흐름을 멈추고 에러를 발생시켜, 잘못된 데이터가 흘러가지 않게 한다.
    📜
    Executions (실행 로그)
    실행 기록에서 어느 노드가·왜 실패했는지 확인한다. 디버깅의 출발점.
    ✨

    Claude 챗 활용: 빨간 에러 로그를 복사해 claude.ai 챗에 붙여 "이 에러 원인이 뭐야?"로 해석 보조를 받을 수 있습니다. (워크플로를 대신 돌리는 건 아님 — 그건 API 키)

    자동화는 실패할 수 있다 — Error Trigger(실패 시 따로 잡기), Stop And Error(일부러 멈춤), 실패 원인은 Executions 실행 로그에서 확인. 막힐 땐 claude.ai 챗에 에러 로그를 붙여 물어보는 디버깅 보조 활용. 의도적 오류(잘못된 시트 ID)를 실행해 빨간 에러를 띄우고 로그를 함께 읽는다.

    트리거(Trigger)와 액션(Action)의 차이로 옳은 것은?

    IF 노드와 Filter 노드의 차이로 옳은 것은?

    해설: IF는 참/거짓 두 출력으로 흐름을 분기하고, Filter는 조건을 통과한 항목만 다음으로 내보냅니다(거짓은 버림).

    "앞 노드의 데이터를 참조할 때 표현식은 {{ $json.상품군 }} 처럼 이중 중괄호 {{ }} 안에 쓴다."

    참. n8n 표현식은 {{ }} 안에 작성하며, {{ $json.필드 }} 로 이전 노드의 데이터를 참조합니다.

    거짓. 실습은 n8n Cloud(매니지드)이고 self-host는 직접 서버를 운영하는 방식입니다. Cloud Business는 self-host 전용 플랜이라 매니지드 실습 플랜이 아닙니다(실습 플랜은 Starter/Pro).
