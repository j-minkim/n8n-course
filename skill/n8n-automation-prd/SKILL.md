# n8n-automation-prd — n8n 자동화 설계 (경량)

"이 업무를 자동화하고 싶어"를 받아 **n8n 워크플로 설계도(자동화 PRD)**를 빠르게 만들고 **n8n 노드로 매핑**한다. superpowers:brainstorming의 깊은 탐색 없이 — **n8n 특화 5섹션 PRD → 6레이어 노드 → (선택) JSON 초안**. 토큰을 아끼는 게 목적이다.

## 왜 이게 따로 있나 (brainstorming과의 차이)
| superpowers:brainstorming | 이 스킬 |
|---|---|
| 범용(코드·앱·뭐든) | **n8n 워크플로 전용** |
| 질문 **하나씩** (긴 왕복) | **5섹션을 한 턴에** 묶어 질문 |
| 접근법 2-3개 비교·탐색 | n8n 6레이어로 **바로 직행** |
| HARD-GATE·긴 승인 | **가벼운 단계 게이트**(설계→JSON→생성 각 확인) |
| 깊지만 토큰 多 | 빠르고 토큰 ↓ |

→ **깊은 설계가 꼭 필요할 때만** superpowers:brainstorming으로 올린다. 보통은 이걸로 충분하다.

## 방법 (이 순서, 가볍게)

### 1) 대상 한 줄 확보 + 핵심 의도 되짚기
자동화할 업무가 한 줄로 잡혔으면 바로 2)로. 없으면 **딱 한 가지만** 묻는다: "어떤 반복 업무를 자동화하고 싶으세요? (예: 매일 아침 뉴스 요약 메일)". 길게 캐묻지 않는다.

★받은 한 줄을 **`내가 이해한 핵심 의도: …`로 한 줄 되짚어** 제시한다 — 사용자가 오해를 즉시 잡게. 의도가 틀리면 5섹션이 통째로 어긋나므로, 이 한 줄만큼은 반드시 확인받고 넘어간다. (이게 brainstorming만큼 깊진 않아도 "내가 뭘 원하는지"를 분명히 하는 최소 장치다.)

### 2) 5섹션 PRD — 한 턴에 (★핵심: 질문을 쪼개지 말 것)
아래 5섹션을 **한 번에** 제시한다. 사용자 입력·맥락에서 **추론할 수 있는 칸은 미리 채우고 `(추정)` 표시**, 모르는 칸만 사용자에게 한꺼번에 묻는다. 절대 한 항목씩 왕복하지 않는다.

```
자동화 PRD — <제목>
① 트리거(언제 시작?)   : 예) 매일 09:00 / 폼 제출 시 / 재고 임계값 이하
② 입력(무엇을 받나?)   : 데이터 소스·형식 (시트/RSS/API/메일/CSV) · 필드
③ 처리(무엇을 하나?)   : 변환·필터·집계 / (AI 판단 필요하면 명시)
④ 출력(어디로?)        : 메일/슬랙/시트/DB
⑤ 예외(실패하면?)      : 오류 알림·재시도·한도(발송량·비용)·개인정보 범위
```
★**5섹션은 언제나 5줄 다 출력**한다 — 미정인 칸도 빈칸으로 두지 말고 `① 트리거: 미정 — 웹폼/이메일/시트 중 선택 필요`처럼 **미정 사유·선택지를 적는다**(절대 ①~⑤ 중 하나라도 누락 금지). 추론으로 채운 칸은 `(추정)`, 모르는 칸은 위처럼 표시하고, **빈칸만 한꺼번에** 1회 질문한다.

★**의도-결정적 칸은 silently 추정하지 말 것 (경량 ≠ 마음 읽기).** ① **트리거**(언제/무엇이 켜나)·④ **출력**(어디로·누구에게)·③ 처리의 **'AI 판단 vs 규칙(IF)' 분기**는 *의도가 갈리는 지점*이다 — 여기를 추측으로 채우면 멀쩡해 보여도 엉뚱한 자동화가 된다. 이 세 가지는 `(추정)`으로 묻어두지 말고 **선택지를 제시해 확인**한다(예: "트리거: 매일 정해진 시각 vs 이벤트 발생 시 — 어느 쪽이세요?"). 반면 데이터 형식·세부 임계값 같은 *비결정적* 칸은 `(추정)`으로 채우고 넘어가도 된다. **가벼움의 핵심은 '질문 수'를 줄이는 것이지 '의도 확인'을 건너뛰는 게 아니다** — 의도-결정 가정 + 빈칸을 **한 번에 묶어** 묻는다(여전히 1턴). 도메인 힌트가 있으면 **권장 기본값을 함께 제안**해 사용자가 막히지 않게 한다(예: "이벤트 시스템이 없으면 A 주기 트리거를 권장 — 웹훅이 되면 B가 더 실시간").

### 3) n8n 6레이어 노드 매핑 (즉시)
PRD 5섹션을 n8n 6레이어로 표 한 개로 변환한다. 노드는 `references/n8n-node-map.md`를 참조(읽어서 정확한 노드명·핵심 파라미터 가져오기). n8n-MCP가 붙어 있으면 MCP로 정확 조회, 없으면 레퍼런스 사용.

```
| PRD            | n8n 레이어 | 노드(예)                    |
| ① 트리거       | 트리거     | Schedule Trigger            |
| ② 입력         | 수집       | RSS Read / Google Sheets    |
| ③ 처리(변환)   | 가공       | Code / Set / Filter         |
| ③ 처리(AI)     | AI 판단    | Anthropic Chat Model(★API키)|
| ④ 출력         | 액션       | Gmail / Slack               |
| ⑤ 예외         | 에러핸들링 | Error Trigger / Stop&Error  |
```

### 4) 게이트 — ★단계를 분리한다 (한 번에 실제 생성까지 가지 말 것)
**한 번의 "OK"로 설계 확정 + JSON 생성 + 실제 n8n 생성을 묶지 않는다.** 특히 수강생 실습에선 위험(되돌리기 어려운 외부 작용).
1. **설계 확정**: 핵심 의도 한 줄 + PRD+매핑을 보여주고 **"이 의도·설계가 맞나요?"** (Yes → 다음 단계). 의도-결정 가정이 아직 미확인이면 여기서 함께 확정한다.
2. **JSON 초안**(원하면): 워크플로 JSON을 만들어 보여주고 **"import할까요?"** → 사용자가 `⋮ → Import from File`. ★거대 JSON 통째 금지 = **노드별 순차 빌드 권장**(cascade 회피).
3. **실제 n8n 직접 생성**(고급): n8n-MCP/API로 n8n에 바로 꽂는 건 **별도 확인** — **"n8n에 직접 만들까요?"**. ★**수강생 실습 기본은 import**, 직접 생성은 **명시 동의 후**에만.
- 표현식·노드명은 "에디터에서 실행해 확인"(환각 — 대소문자·`$json.` 접두사).

### 5) (선택) JSON 초안
사용자가 원하면 워크플로 JSON을 만든다. `name·nodes·connections·settings` 최소 구조. n8n API가 있으면 `POST /api/v1/workflows`로 직접 생성도 가능(자료의 API 키 절차 참조).

## 원칙
- **토큰 절약 최우선**: 긴 탐색·접근법 비교·항목별 왕복 금지. 5섹션 한 턴 → 매핑 → **단계 게이트**(설계 확정 → JSON 초안 → 실제 생성, 각 별도 확인). (가벼움 ≠ 한 번에 다 진행: 외부 작용은 단계로 끊는다.)
- **경량 ≠ 마음 읽기 (의도는 분명히)**: 토큰을 아끼되 *무엇을 원하는지*는 분명히 잡는다 — 핵심 의도 1줄 되짚기 + 의도-결정적 가정(트리거·출력·AI vs 규칙) 확인은 생략하지 않는다. brainstorming만큼 깊진 않아도, "엉뚱한 걸 정확히 만드는" 사고는 막는다.
- **n8n 특화**: 노드 지식은 `references/n8n-node-map.md`. 모르는 노드는 MCP 조회 or "에디터에서 확인".
- **사실 정확**: ★워크플로 안 Anthropic 노드 = 별도 Anthropic API 키(종량과금), Claude Pro 구독 불가. n8n API 키(외부 제어) ≠ Anthropic API 키. 단정 어려운 노드 파라미터·버전은 "당일/에디터 확인" 톤.
- **깊이가 필요하면 위임**: 진짜 모호하거나 큰 설계면 그때 superpowers:brainstorming으로.
- **★빌드 깊이는 외부 자료에 위임 (공식 우선)**: 정확한 노드 파라미터·검증·에러·Code 패턴 같은 깊은 빌드 지식은 **① 공식 `n8n-io/skills`를 우선**으로, ② 고급/대체로 **`czlonkowski/n8n-skills`**(MIT·14스킬: 표현식·MCP툴·워크플로 패턴·검증·노드설정·Code·에러·AI Agent·셀프호스팅), ③ 실시간 정확 조회는 **n8n-MCP**가 담당한다. 이 스킬은 *가벼운 설계 진입점*일 뿐 — 빌드 단계에서 그것들을 부른다. (핵심 노드값·gotcha는 `references/n8n-node-map.md`에 흡수돼 외부 미설치여도 설계는 굴러간다.)

## 출력 형식 (항상)
1. **자동화 PRD**(5섹션 전부, 미정·추정 표시) 2. **n8n 6레이어 매핑 표** 3. **단계 게이트**: ⓐ "이 설계가 맞나요?"(설계 확정) → ⓑ "JSON 초안 만들까요?" → ⓒ "n8n에 직접 만들까요?"(별도 확인) 4. 단계별로만 진행(★실습 기본 = import, 직접 생성은 명시 동의 후).
