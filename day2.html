🧱 핵심 개념

복합 워크플로우 = 단일 워크플로의 조합

하나의 작업(시트 읽기, 메일 보내기)이 아니라, 여러 작업을 이어 붙여 업무 한 사이클 전체를 자동으로 굴리는 것.

•
단일 워크플로 (1일차)
"편성표 읽어서 메일 보내기" 처럼 한 가지 일만 끝까지. 트리거 1 + 노드 2~3개.
🔗
복합 워크플로 (오늘)
수집→가공→판단→액션→알림이 한 흐름. 예: 매출 읽고 → 집계하고 → AI로 요약하고 → 시트 쓰고 → 여러 명에게 발송 → 실패 시 에러 처리.

오늘의 목표는 "노드를 더 배우는 것"이 아니라 흐름을 설계하는 것입니다.

지금까지는 단일 워크플로(편성표→메일, 매출 집계→발송 각각). 오늘은 복합 — 단일들을 조합해 하나의 업무 사이클을 통째로 자동화. 어제 만든 단일 2개를 화면에 띄워 "이걸 합칠 거예요" 시각화.
⚠️ 흔한 오개념

"한 번 만들면 알아서 굴러간다" — 아니요

⚠️

오개념 ①: "워크플로는 한 번 만들면 영원히 잘 돈다." → 시트 구조가 바뀌거나, 빈 행이 들어오거나, 외부 서비스가 잠깐 죽으면 그대로 멈추거나 잘못된 메일을 발송합니다.

⚠️

오개념 ②: "AI 노드는 개인 Claude 구독(claude.ai)만 있으면 워크플로 안에서 바로 쓸 수 있다." → 워크플로 AI 노드는 별도 Anthropic API 키가 있어야 동작합니다. (뒤에서 자세히)

✅

그래서 오늘 복합 워크플로에는 에러 핸들링을 반드시 같이 설계합니다. 자동화는 "만들고 끝"이 아니라 "만들고 지키는" 것입니다.

"한 번 만든 워크플로는 시트 구조가 바뀌어도 알아서 잘 돈다." — 참일까요, 거짓일까요?

거짓. 시트 구조 변경·빈 행·외부 서비스 장애가 생기면 그대로 멈추거나 잘못된 메일을 발송합니다. 그래서 에러 핸들링을 함께 설계해 "만들고 지키는" 자동화로 만들어야 합니다.
복합으로 갈수록 에러 처리가 더 중요 — 노드가 많아지면 실패 지점도 많다. 그래서 오늘 실습엔 에러 핸들링이 꼭 들어간다. 1일차 반복이라 한 줄로 가능.
📐 설계 방법론 (M7)

업무를 노드로 옮기는 3단계

복합 워크플로를 처음부터 짜려 하면 막막합니다. 항상 이 순서로 분해하세요.

  • 1업무 프로세스 적기
    "매주 월요일에 매출 시트를 열어 → 상품군별로 더하고 → 요약을 정리해 → 팀장과 팀 메일에 보낸다" — 평소 손으로 하는 순서를 문장으로.
  • 2단계별 노드 매핑
    각 문장을 n8n 노드로 1:1 대응. "매출 시트 열기 → Google Sheets(Get)", "보낸다 → Gmail".
  • 3연결 설계
    노드를 순서대로 잇고, 데이터가 다음 노드로 어떻게 넘어가는지(표현식 매핑)·어디서 갈라지는지(분기)를 정한다.
복합 설계법: 업무 프로세스를 먼저 그리고→각 단계를 노드로 매핑하고→연결한다. 머릿속 업무 순서를 그대로 노드로 옮기는 것. 밀리면 한 줄로.

오늘 실습의 척추 — 6단계 템플릿: 트리거→수집→가공→판단→액션→알림. 거의 모든 자동화가 이 틀에 들어간다. 손으로 하나씩 짚으며 리듬 있게 읽고 입으로 외우게 한다(F10: "트리거→?" 같이 외치기).
① 단계 상세 · 앞 3칸

앞 3칸: 언제 → 어디서 → 어떻게

각 칸은 하나의 질문에 답합니다. 질문에 답하면 대응 노드가 자동으로 정해집니다 — 주간 리포트로 한 줄씩 채워 봅니다.

1 트리거 언제 시작?
대응 노드: Schedule / Webhook.
주간 리포트: 매주 월 09:00(Asia/Seoul) → Schedule Trigger.
2 수집 어디서 데이터?
대응 노드: Google Sheets Get / HTTP Request.
주간 리포트: 사내 매출 시트 읽기 → Google Sheets (Get).
3 가공 어떻게 변환·집계?
대응 노드: Edit Fields(Set) / Summarize(Aggregate).
주간 리포트: 상품군별/방송별 매출 합산 → {{ $json.상품군 }} 키로 group + sum.
앞 세 단계(데이터 준비 앞단): 트리거=언제 시작(스케줄/웹훅), 수집=어디서 데이터(시트/API), 가공=어떻게 변환·집계(어제 표현식·집계). 6단계의 확장이라 짧게, 줄이지는 말 것.
② 단계 상세 · 뒤 3칸

뒤 3칸: 판별 → 실행 → 통지

'판단'이 가장 헷갈립니다. 핵심은 "판단=무조건 AI"가 아니라는 것 — 무엇을 가르느냐에 따라 노드가 달라집니다.

4 판단 분기 / AI?
숫자 임계값(목표매출 미달 등)이면 IF로 충분·정확. 자유 텍스트(CS 문의 분류)면 AI 노드. → 임계값인데 AI를 쓰는 건 과설계.
5 액션 무엇을 실행?
대응 노드: Google Sheets Append / Gmail.
주간 리포트: 요약 시트 쓰기 + 메일 발송.
6 알림 누구에게?
대응 노드: Gmail(다중 수신).
주간 리포트: 팀장 + 팀 메일링리스트 발송 + 실패 시 에러 알림.
⚠️

오개념 교정(E3 모범답안): "판단=무조건 AI"가 아닙니다. 조건이 숫자 비교면 IF가 더 단순·정확하고, 자연어 분류(CS 문의)일 때만 AI 노드가 필요합니다.

뒤 세 단계(처리·내보내기 뒷단): 판단=조건/AI로 결정(IF 분기/AI 분류), 액션=뭘 실행(시트 쓰기·메일), 알림=누구에게(팀장·메일링리스트). 6단계 확장이라 짧게.

🔑 반드시 구분 · 검증된 사실

'판단'에 쓸 AI: 개인 Claude 구독 ≠ API 키

이름이 둘 다 "Claude"라 헷갈립니다. 하지만 둘은 완전히 다른 것이고, 워크플로 안에서 쓸 수 있는 건 오른쪽뿐입니다.

💬
개인 Claude 구독 (claude.ai)
claude.ai 챗 구독. 설계 아이디어 잡기·표현식 작성·에러 로그 해석 같은 보조용. 워크플로 AI 노드는 구동 불가.
🔌
Anthropic API 키
console.anthropic.com에서 발급하는 별도 키. n8n의 Anthropic Chat Model 노드는 이 키가 있어야만 동작. → 회사 제공 오늘 직접 핸즈온.
ℹ️

핵심은 가격이 아니라 접근 방식입니다 — 개인 구독은 claude.ai 안에서만 쓰이고, 워크플로 AI 노드는 별도 발급한 API 키로만 연결됩니다.

"개인 Claude 구독(claude.ai)만 있으면 n8n 워크플로 안 AI 노드를 바로 구동할 수 있다."

거짓. 워크플로의 Anthropic Chat Model 노드는 console.anthropic.com에서 발급한 별도 API 키가 있어야 동작합니다. 개인 claude.ai 구독은 챗·보조용일 뿐 워크플로 AI 노드는 구동하지 못합니다.

🧪 본실습 · M7b

매주 자동 실행되는 주간 성과 리포트 만들기

두 개의 체크포인트 게이트로 나눠 진행합니다. 각 게이트에서 "실행 녹색"을 확인하고 다음으로 넘어갑니다.

게이트 ① 전반 — 집계까지
스케줄 → 매출 시트 읽기 → 상품군별/방송별 집계 → 요약 시트 쓰기. 70분 지점에서 요약 시트에 값이 쓰였는지 확인.
게이트 ② 후반 — 발송·에러·AI
요약 포맷팅 → 팀장 + 메일링리스트 다중발송 → 에러 핸들링 → AI 분류/요약 노드 연결.
🛟

각 게이트에서 막혀도 괜찮습니다 — 강사가 준비한 중간 완성 워크플로 import 파일(.json)을 불러와 다음 게이트부터 합류합니다. 전원이 끝까지 완성합니다.

오늘 메인: 주간 성과 리포트. 스케줄(월요일)→매출 수집→집계→요약 시트→포맷팅→다중발송→에러 핸들링→CS AI 분류. 두 게이트(전반=요약 시트까지, 후반=발송·에러·AI)로 나눠 진행, 각 게이트 끝에 녹색 확인. 못 따라오면 중간 완성 import 파일로 합류 — 아무도 뒤처지지 않음.
🌐 스케줄 전 필수 · 검증된 사실

스케줄을 짜기 전에 타임존부터

n8n Cloud는 가입 시 타임존을 자동 감지하지만, 감지에 실패하면 기본값이 GMT입니다. 그러면 "매주 월 09:00"이 한국 시간 18:00에 돌 수 있습니다.

  • 확인 경로: Cloud 대시보드 → Manage → Timezone 드롭다운에서 Asia/Seoul (UTC+9) 선택.
  • 워크플로별로 따로 지정하려면 Workflow Settings에서 오버라이드 가능.
  • 스케줄 본실습을 시작하기 전, 한 번만 확인하면 됩니다.
시작 전 타임존 필수 점검: Cloud Manage→Timezone이 Asia/Seoul인지 확인. GMT면 월요일 8시가 영국 8시(9시간 차)라 매주 엉뚱한 시각에 리포트 발송. 실제 화면을 열어 함께 설정.

🕸️ AI 노드 구조 · 본실습 준비

AI 노드는 두 조각: 루트 체인 + 서브 모델

AI 판단은 노드 하나가 아니라 루트(체인) + 서브(모델) 두 노드의 조합입니다. 역할을 헷갈리면 실행이 안 됩니다.

🔗
Basic LLM Chain (루트)
실제로 호출·실행되는 노드. 프롬프트는 여기에 넣습니다(분류·요약 지시). 흐름의 main 선에 놓입니다.
🧩
Anthropic Chat Model (서브)
체인의 Chat Model(ai_languageModel) 자리에 꽂히는 서브노드. Credential(회사 API 키)은 여기에 등록합니다.

⚠️

이 강의 최대 함정: Anthropic Chat Model은 단독 실행이 안 되는 서브노드입니다. "Chat Model만 추가하고 실행"하면 동작하지 않습니다 — 반드시 Basic LLM Chain 같은 루트 노드에 연결해야 돕니다.

"Anthropic Chat Model 노드는 캔버스에 혼자 두고 실행해도 동작한다."

거짓. Anthropic Chat Model은 단독 실행이 안 되는 서브노드입니다. Basic LLM Chain(루트)의 Chat Model(ai_languageModel) 자리에 연결하고 체인을 실행해야 동작합니다.
오늘의 하이라이트 — 키 넣기 전 구조부터: AI는 노드 두 개가 한 쌍. Basic LLM Chain이 루트(프롬프트·실행은 여기), 그 Chat Model 자리에 Anthropic Chat Model을 끼움(서브). 핵심: Anthropic Chat Model은 혼자 못 돌고 반드시 체인에 꽂혀 있어야 동작. 캔버스에서 한 쌍 연결해 "모델 단독 실행 불가" 1회 강조.
🧠 AI 핸즈온 1/2 · LO4b

'판단' 단계에 AI 노드 붙이기 — Basic LLM Chain + Anthropic Chat Model

AI 판단은 루트 노드인 Basic LLM ChainBasic LLM Chain — LLM 모델 노드를 감싸 실제로 호출·실행하는 n8n 루트 노드. 프롬프트를 여기에 넣고, 모델(Chat Model)을 자식으로 연결한다. Chat Model만으로는 단독 실행되지 않는다.에 프롬프트를 넣고, 그 체인의 Chat Model 자리에 Anthropic Chat Model을 연결해 구동합니다.

🔑

워크플로의 AI 노드는 회사가 제공한 Anthropic API 키로 연결합니다 — 개인 Claude 구독(claude.ai)으로는 동작하지 않습니다. 키는 그 모델 노드에 한 번만 등록하면 됩니다.

  • 1회사 제공 API 키 확인 — console.anthropic.com → Settings → API Keys에서 발급된 키 (회사가 미리 준비·배포)
  • 2n8n Credentials 등록 — Credentials → New → Anthropic API → API Key 칸에 붙여넣기
  • 3Basic LLM Chain(루트) 추가 — '판단' 자리에 체인 노드를 놓고 프롬프트 입력(분류·요약 지시)
  • 4Anthropic Chat Model 연결 — 체인의 Chat Model(ai_languageModel) 자리에 붙이고, 방금 만든 Credential(회사 키)을 선택
  • 5체인 실행 — Basic LLM Chain을 실행해 결과 확인
⚠️

함정: Anthropic Chat Model은 단독 실행이 안 되는 서브노드(ai_languageModel)입니다 — 반드시 Basic LLM Chain 같은 루트 노드에 연결해야 동작합니다. "Chat Model만 추가하고 실행" 하면 작동하지 않습니다.

Anthropic Chat Model 노드의 Credential에서 New→Anthropic API로 회사가 제공한 API 키를 붙여넣는다. 워크플로 AI 노드는 회사 제공 Anthropic API 키로 연결되며 개인 Claude 구독(claude.ai)으로는 동작 안 함. claude.ai 로그인돼 있다고 그냥 되는 게 아님 — 회사 키를 Credential에 넣어야 비로소 연결. 401 폭주 예상, "회사 키를 Credentials에" 반복(F13).

단순 규칙(IF)으로는 못 가르는 자유 텍스트를 AI가 판단합니다. 결과는 다시 시트/메일로 흘려보냅니다.

⬇️
입력
CS 문의 텍스트 (시트의 문의 내용 열). 예: "주문한 상품이 아직 안 왔어요" "사이즈 교환 가능한가요"
✨
AI 처리 + 출력
Basic LLM Chain(모델 = Anthropic Chat Model)이 카테고리(배송/교환/환불…) 분류 + 한 줄 요약 생성 → Google Sheets/Gmail 노드로 연동.
✅

체크포인트: AI 노드가 녹색으로 실행되고, 분류·요약 결과가 시트 또는 메일에 기록되면 LO4b 달성. (회사 API 키로 호출되므로 필요한 만큼만)

CS 문의 더미 시트를 Get Row(s)로 읽고 Basic LLM Chain에 프롬프트를 주고 실행(모델은 연결한 Anthropic Chat Model이 맡음): "다음 CS 문의를 배송·환불·상품문의·기타 중 하나로 분류하고 한 줄로 요약: {{ $json.문의내용 }}". 결과를 시트 Append하거나 메일 발송하면 판단 단계 완성. 막히면 분류만(요약 생략) 시켜도 됨.

AI가 제멋대로 답하지 않게 — 라벨·형식 고정

같은 프롬프트라도 출력을 좁혀 두면 결과가 일관되고 후속 자동화(파싱)가 쉬워집니다. 두 가지만 지키세요.

🏷️
① 허용 라벨 고정
"[배송/환불/상품문의/기타] 중 하나로만" 명시. 안 하면 모델이 라벨을 제각각으로 붙여 분류가 흩어집니다.
{ }
② JSON 형식 강제
{"분류":"…","요약":"…"} 형식으로만 답하게 강제 → 후속 시트/메일 파싱이 쉬워집니다.
⚠️

401 / authentication 에러: 개인 Claude 구독(claude.ai)으로 착각했거나 API 키 미입력일 때 납니다 — Credentials에 회사 제공 Anthropic API 키를 입력하세요.

"허용 라벨을 고정하지 않아도 AI 분류 라벨은 일정하게 나온다."

거짓. 라벨을 고정하지 않으면 모델이 분류를 제각각으로 붙입니다. "[배송/환불/상품문의/기타] 중 하나로만" 명시하고 JSON 형식을 강제해야 일관성과 후속 파싱이 보장됩니다.
결과가 들쭉날쭉하면 십중팔구 프롬프트 문제. 요령 3: ①출력 형식 고정(배송/환불/상품문의/기타 중 하나로만 — 허용 라벨 명시) ②역할·작업 명확히("너는 CS 분류기, 라벨 1개+한 줄 요약만") ③입력을 표현식으로 정확히({{ $json.문의내용 }}). 라벨 안 고정 vs 고정 출력 차이를 1회 대비 시연(F14).
🛡️ 안전망 · 검증된 노드

실패해도 조용히 망가지지 않게

복합 워크플로는 노드가 많을수록 어딘가 한 곳이 실패할 확률이 올라갑니다. 두 가지 노드로 대비합니다.

🔔
Error Trigger
워크플로가 실패하면 별도 흐름을 자동 실행 — 예: 담당자에게 "리포트 자동화 실패" 알림 메일.
🛑
Stop And Error
데이터가 비었거나 형식이 틀리면 의도적으로 멈추고 명확한 에러 메시지를 남김 — 잘못된 메일 발송 방지.
  • 실행 로그 확인 — 각 노드의 입출력 데이터를 눌러보며 어디서 멈췄는지 추적.
  • 개인 Claude 구독(claude.ai 챗·보조)으로 에러 로그를 붙여넣고 원인 해석을 도움받기 — API 키 없이도 가능한 디버깅 활용.
에러 핸들링은 노드 하나 붙였다로 끝내면 안 되고 의도적으로 오류를 내서 로그에 잡히는지 직접 확인해야 진짜. 실패를 알아채는 게 유지보수 핵심. 대량·장시간이면 Cloud 100초 초과 시 끊김·페이로드 16MB — 크면 배치로 쪼갠다.

👥 그룹토의 (M8)

2분 시연 + 동료 피드백 1개

완성도보다 "작게라도 동작하는 것"이 핵심입니다. 서로의 워크플로를 한 가지 기준으로 비평합니다.

🖥️
발표자 — 2분 시연
① 어떤 반복 업무인지 ② 설계 템플릿 6칸 ③ 실제 실행(녹색) 한 번 보여주기.
💬
동료 — 개선 피드백 1개
"에러 핸들링을 추가하면?" "이 단계는 분기로 나누면?" 처럼 구체적 개선점 하나를 제안.

피드백은 평가가 아니라 다음 워크플로를 위한 재료입니다. 받은 피드백 1개를 메모해 가져가세요.

한 분씩 또는 조별 2분 시연 — 완벽 안 해도 됨, "이런 반복 업무를 이렇게 자동화했다"면 충분. 듣는 사람은 박수만 말고 구체적 개선점 하나씩(트리거를 웹훅으로·에러 핸들링 추가 등). 시간상 자원자 3~4명 중심, 모호한 칭찬은 "구체적으로 어느 노드?"로 되묻기.
🎯 마스터리 체크

오늘 끝에 이걸 할 수 있으면 성공

클릭해서 스스로 점검해 보세요. 막히는 항목이 있으면 해당 본실습 슬라이드로 돌아가면 됩니다.

  • ○ 설계 템플릿(트리거→수집→가공→판단→액션→알림)으로 복합 워크플로를 설계할 수 있다
  • ○ 주간 리포트(집계→요약→다중발송→에러 핸들링)를 직접 구성·실행할 수 있다
  • ○ Basic LLM Chain + Anthropic Chat Model(회사 API 키)로 CS 문의를 분류/요약할 수 있다
  • ○ 워크플로 AI 노드는 개인 Claude 구독으로는 못 돌리고 회사 Anthropic API 키가 필요하다는 점을 설명할 수 있다
  • ○ 내 업무 반복작업을 템플릿에 매핑해 미니 워크플로를 만들 수 있다

종합 시험

제출 전까지 정답은 숨겨집니다. 3문항을 다 고른 뒤 "제출하고 채점"을 누르세요. (미응답은 오답 처리)

"설계 템플릿 6단계의 순서는 트리거 → 수집 → 가공 → 판단 → 액션 → 알림이다."

참. 오늘 실습의 척추인 6단계 템플릿은 트리거(언제) → 수집(어디서) → 가공(어떻게) → 판단(조건/AI) → 액션(무엇을) → 알림(누구에게) 순서입니다.

"n8n의 AI 노드는 루트 체인(Basic LLM Chain / AI Agent)에 서브 모델(Anthropic Chat Model)을 연결하는 구조다."

참. 루트 노드(Basic LLM Chain·AI Agent)에 서브 모델 노드(Anthropic Chat Model)를 붙여 동작합니다. 이때 워크플로 AI 노드는 개인 Claude 구독이 아니라 회사 Anthropic API 키가 필요합니다.

"프롬프트로 분류 결과를 받을 때는 라벨을 매번 자유롭게 바꿔도 다음 노드가 똑같이 처리한다."

거짓. 분류 라벨은 고정해야 뒤따르는 IF/Switch 분기가 안정적으로 매칭됩니다. 라벨이 매번 달라지면 후속 노드가 조건을 못 맞춰 흐름이 깨집니다.

오답 문항은 위 해설을 확인하고, 필요하면 해당 본실습 슬라이드로 돌아가 다시 학습하세요.
이틀 마스터리 점검(손들기 자가점검): 6단계 템플릿으로 복합 워크플로를 설계하고, 에러 핸들링을 붙이고, 워크플로 안 AI 노드를 돌리고, 내 업무를 직접 자동화했다. 밀리면 한 줄로 압축.
🏁 2일차 마무리 (M9)

"월요일에 바로 켤 자동화 하나"를 정하고 끝냅니다

배운 것을 다 쓰려 하지 말고, 가장 효과 큰 하나를 골라 실제로 켜는 것 — 그게 자동화 전문가의 첫걸음입니다.

🚀

업무 자동화 전문가의 역할: 반복 프로세스를 발견하고 → 자동화 워크플로로 설계하고 → 구축하고 → 유지보수한다. 오늘 네 단계를 모두 한 번씩 해봤습니다.

  • 다음 단계 자료: Docker self-host 셋업 가이드(문서·참고용), Anthropic API 키 적용 가이드(회사 키 입력 절차).
  • 기억할 구분: 실습 환경 = n8n Cloud / 타임존 = Asia/Seoul / 워크플로 AI 노드 = 회사 Anthropic API 키 연결(개인 Claude 구독으로는 불가) / Gmail 발송 한도 = Workspace 2,000·무료 500건/일.

코딩 없이, 매주 손으로 하던 리포트를 자동으로 — 이제 내 업무 차례입니다.

제일 중요한 마무리 — 머릿속 워크플로는 안 켜면 의미 없으니 "이번 주 월요일에 실제로 켤 자동화 하나"를 지금 정하게 한다(전이 약속). self-host·워크플로 API 키 넣는 법은 핸드아웃 가이드. 개인 Claude 구독과 API 키는 별개라는 걸 마지막으로 한 번 더 못 박고 종료.
