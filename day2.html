    🪄 M4 · /n8n-automation-prd

    5섹션을 한 번에 뽑고, 단계로 안전하게 짓는다

    자동화 설계 전용 경량 스킬입니다. 질문을 하나씩 캐묻지 않고 5섹션 PRD를 한 턴에 만들어 줘요 — 비는 칸만 한꺼번에. 단, 핵심 의도와 트리거·출력 같은 결정적 선택은 꼭 확인합니다(경량이어도 엉뚱한 걸 만들지 않게).

    /n8n-automation-prd
# "○○를 자동화하고 싶어" 한 줄이면 시작
# → 5섹션 PRD(트리거·입력·처리·출력·예외)를 한 번에 + n8n 6레이어 매핑
# → 단계 게이트: ① 설계 확정 → ② JSON 초안 → ③ 실제 생성(별도 확인)
    왜 경량인가
    범용 brainstorming은 한 질문씩·접근법 비교로 토큰을 많이 씁니다. 이 스킬은 n8n 전용이라 보통 1턴에 끝나요.
    단계 게이트 = 안전
    한 번의 "OK"로 실제 생성까지 가지 않습니다. 설계 확정 → JSON 초안 → 실제 생성을 끊어서. 실습 기본은 import.
    🌿

    언제 brainstorming? 정말 크고 모호한 설계(여러 제품·복잡한 정책)면 그때만 /superpowers:brainstorming으로 올립니다. 보통의 업무 자동화는 이 경량 스킬로 충분합니다.

    핵심 교체: brainstorming(무겁고 토큰多·질문 하나씩) → 경량 전용 스킬 /n8n-automation-prd(5섹션 한 턴·빈칸만 한꺼번에). 안전장치는 HARD-GATE가 아니라 단계 게이트(설계확정→JSON초안→실제생성, 실습 기본 import). brainstorming은 정말 복잡한 설계의 폴백으로만. "전용 스킬이 가볍고 정확"이 AI-native 메시지.
    📋 M4 · 자동화 PRD 5섹션

    모든 자동화는 이 5칸으로 적힙니다

    • 트
      ① 트리거 (언제)스케줄? 외부 호출? 폼 제출? — 무엇이 흐름을 켜는가.
    • 입
      ② 입력 (무엇을 받나·형식)시트/메일/HTTP 등 어디서 어떤 데이터를 가져오나.
    • 처
      ③ 처리 (변환·판단·AI)필터·집계·매핑, 그리고 필요하면 AI 판단(분류·요약).
    • 출
      ④ 출력 (어디로)시트 쓰기/메일/Slack 등 결과를 어디로 보내나.
    • 예
      ⑤ 예외·한도 (실패·재시도·비용·개인정보)실패하면? 발송 한도·API 비용·민감정보는?
    👥

    짝 리뷰: 옆 사람 PRD에서 가장 자주 비는 칸은 ⑤ 예외·한도입니다. 서로 1개씩 비었는지 지적해 주세요.

    PRD 5섹션: 트리거·입력·처리(변환/AI)·출력·예외/한도. ⑤가 가장 자주 빈다 → 짝 리뷰로 보완. 이 5칸이 다음 슬라이드에서 n8n 6레이어로 매핑된다.

    🧱 M7 · 핵심 개념

    복합 워크플로 = 단일 워크플로의 조합

    하나의 작업(시트 읽기, 메일 보내기)이 아니라, 여러 작업을 이어 붙여 업무 한 사이클 전체를 자동으로 굴리는 것.

    •
    단일 워크플로 (1일차)
    "편성표 읽어서 메일 보내기" 처럼 한 가지 일만 끝까지. 트리거 1 + 노드 2~3개.
    🔗
    복합 워크플로 (오늘)
    수집→가공→판단→액션→알림이 한 흐름. 예: 매출 읽고 → 집계하고 → AI로 분류하고 → 시트 쓰고 → 여러 명에게 발송 → 실패 시 에러 처리.

    오늘의 목표는 "노드를 더 배우는 것"이 아니라 흐름을 설계하는 것입니다. 설계가 먼저, 빌드는 그 다음.

    지금까지는 단일 워크플로(편성표→메일, 매출 집계→발송 각각). 오늘은 복합 — 단일들을 조합해 하나의 업무 사이클을 통째로 자동화. 어제 만든 단일 2개를 화면에 띄워 "이걸 합칠 거예요" 시각화.
    🗺️ 설계 템플릿 · 핵심 (IMG-06 재등장)

    모든 복합 워크플로는 이 6레이어로 환원됩니다

    1일차 PRD 5섹션이 그대로 6레이어로 내려옵니다. 이 템플릿이 오늘 본실습과 내 업무 적용의 공통 뼈대입니다.

    오늘 실습의 척추 — PRD 5섹션이 6레이어로 내려온다: 트리거→수집→가공→판단(IF or AI)→액션·알림→에러핸들링. 손으로 하나씩 짚으며 리듬 있게 읽고 "트리거→?"로 청중이 외치게 한다.
    🤖 AI-native 빌드 원칙 · ★핵심

    경량 스킬 PRD → Claude Code+n8n-MCP 노드별 순차 빌드

    복합 워크플로를 한 번에 만들려 하지 마세요. 설계도(PRD)를 먼저 잡고, 노드를 하나씩 붙이며 즉시 검증합니다.

    코드 · 화면에서 함께 입력 (Claude Code) 설계 → 빌드 호출 예시
    /n8n-automation-prd → "주간 매출 리포트를 자동화하고 싶어." (5섹션 PRD 한 번에) (설계 확정 후, n8n-MCP 연결 상태에서) → "이 PRD대로 Schedule Trigger 노드부터 JSON으로 만들어줘. 한 번에 다 만들지 말고 노드 하나씩."
    ⚠️

    ★거대 JSON 통째 생성 금지(cascade): AI에게 "워크플로 전체 JSON을 한 번에" 시키면 노드 하나가 어긋날 때 줄줄이 에러가 나 어디서 깨졌는지 못 찾습니다. 노드별로 만들고 → 붙이고 → 즉시 실행·검증해야 문제를 바로 격리합니다.

    오늘 빌드의 대원칙: PRD 먼저(경량 스킬 /n8n-automation-prd로 5섹션 한 번에·단계 게이트), 그다음 n8n-MCP로 정확한 노드 조회하며 노드 하나씩 빌드·검증. "전체 JSON 한 방"은 금지 — 어긋나면 cascade로 다 깨져 디버깅 불가. import는 낙오 합류용일 뿐 정석은 순차 빌드. 라이브에서 통째 생성 유혹 들면 참는다.
    🔑 '판단' 레이어 · 반드시 구분

    '판단'에 쓸 AI: 개인 Claude 구독 ≠ 워크플로 API 키

    6레이어의 '판단'에서 자유 텍스트(CS 문의 분류)를 가르려면 AI 노드를 씁니다. 그런데 이 노드는 1일차에 쓴 Claude Code·Pro 챗과 결제가 다릅니다.

    💬
    개인 Claude 구독 (Pro 등)
    claude.ai 챗 / Claude Code 보조용. 설계·표현식 작성·에러 로그 해석에 쓰임. 워크플로 안 AI 노드는 이걸로 못 돕니다.
    🔌
    워크플로 Anthropic 노드 = 별도 API 키
    n8n Anthropic Chat Model 노드는 console.anthropic.com에서 발급한 API 키(종량과금)가 있어야만 동작. → 회사 제공 M8에서 직접 입력.
    ℹ️

    ★Claude Pro 구독으로 워크플로 AI 노드를 구동할 수 없습니다. Pro는 claude.ai 챗 한도일 뿐이고, 워크플로 노드는 별도 API 키(쓴 만큼 과금)로만 연결됩니다. (15-factcheck V-B4 ✅)

    M8 AI 핸즈온 직전 예방주사 — 워크플로 Anthropic 노드는 회사가 준 Anthropic API 키(종량과금)로만 돈다. 개인 Claude Pro 구독으로는 안 됨(이름이 같아 100% 헷갈림). 1일차 Claude Code/Pro 챗과 별개. 실습에서 401 뜨면 십중팔구 이 오해. "워크플로=API 키, 챗=구독" 1회 못 박기.
    ✅ 빌드 리듬

    노드 하나 붙일 때마다 한 번 실행

    "다 만들고 마지막에 한 번 실행"이 아니라, 노드마다 즉시 검증하면 환각·표현식 오류를 바로 잡습니다.

    • 1n8n-MCP로 노드 조회
      "Schedule Trigger 노드의 정확한 파라미터 알려줘" — AI가 노드명·필드를 지어내지 않도록 정확 정보를 받음.
    • 2노드 1개 붙이기
      받은 JSON에서 노드 하나만 캔버스에 추가하거나 직접 설정.
    • 3즉시 실행(Test step)
      그 노드만 실행해 출력 데이터를 눈으로 확인 — 표현식 {{ $json.필드 }} 대소문자·접두사 오류를 여기서 잡음.
    • ✓녹색이면 다음 노드
      녹색 확인 후에만 다음 노드로. 막히면 에러 로그를 Claude Code에 붙여 해결.
    ✅

    이 리듬이 곧 "AI 초안 → 에디터에서 검증"입니다. AI는 빠른 파트너지, 무조건 맞는 정답기가 아닙니다.

    순차 빌드의 실제 리듬: MCP로 노드 정보 조회→노드 1개 붙임→그 노드만 Test step 실행→녹색이면 다음. 표현식 환각(대소문자·$json. 접두사 누락)은 노드 단위 실행으로 즉시 잡힘. "AI가 줬으니 맞겠지"가 사고의 원인. 노드 하나 실행을 직접 시연.
    🧪 M8 · 중심문제

    매주 자동 실행되는 주간 성과 리포트 만들기

    두 개의 체크포인트 게이트로 나눠 진행합니다. 각 게이트에서 "실행 녹색"을 확인하고 다음으로 넘어갑니다.

    체크포인트 ① 전반 — 집계까지
    스케줄 → 매출 시트 읽기 → 상품군별/방송별 집계 → 요약 시트 쓰기. 요약 시트에 값이 쓰였는지 확인.
    체크포인트 ② 후반 — 발송·에러·AI

    IF와 Filter는 무엇이 다른가

    🔀
    IF — 두 갈래
    true / false 두 출력이 생긴다. 양쪽을 각각 다르게 후속 처리할 때.
    예: 미달 방송은 요약 시트에, 달성 방송은 통과.
    🧹
    Filter — 거르기
    통과 아이템만 남기고 나머지는 버린다(분기 없음).
    예: 빈 행·목표 달성 행을 빼고 미달 행만 다음으로.
    ⚠️

    흔한 실수: 매출이 "1,200,000"처럼 문자열이면 숫자 비교가 항상 실패합니다 → 콤마 제거 후 Number로 변환해 비교하세요.

    "통과할 아이템만 남기고 나머지는 버리되, 분기는 만들지 않는다" — 어느 노드일까요?

    정답: B. Filter는 통과 항목만 남기고 분기를 만들지 않습니다. 두 갈래(참/거짓)로 나누는 건 IF입니다.
    IF=참/거짓 두 출력으로 분기, Filter=통과만 남기고 버림(분기 없음). 문자열 매출은 숫자 비교 실패 → 콤마 제거+Number 변환. 표현식 환각은 다음 슬라이드.

    AI 노드는 두 조각: 루트 체인 + 서브 모델

    AI 판단은 노드 하나가 아니라 루트(체인) + 서브(모델) 두 노드의 조합입니다. 역할을 헷갈리면 실행이 안 됩니다.

    🔗
    Basic LLM Chain (루트)
    실제로 호출·실행되는 노드. 프롬프트는 여기에 넣습니다(분류·요약 지시). 흐름의 main 선에 놓입니다.
    🧩
    Anthropic Chat Model (서브)
    체인의 Chat Model(ai_languageModel) 자리에 꽂히는 서브노드. Credential(회사 API 키)은 여기에 등록합니다.
    flowchart LR P["프롬프트
    (분류·요약 지시)"] --> C["Basic LLM Chain
    루트 · 실행됨"] M["Anthropic Chat Model
    서브 · 회사 API 키"] -. ai_languageModel .-> C C --> O["분류 + 한 줄 요약
    → 시트/메일"]
    ⚠️

    이 강의 최대 함정: Anthropic Chat Model은 단독 실행이 안 되는 서브노드입니다. "Chat Model만 추가하고 실행"하면 동작하지 않습니다 — 반드시 Basic LLM Chain 같은 루트 노드에 연결해야 돕니다.

    키 넣기 전 구조부터: AI는 노드 두 개가 한 쌍. Basic LLM Chain이 루트(프롬프트·실행은 여기), 그 Chat Model 자리에 Anthropic Chat Model을 끼움(서브). 핵심: Anthropic Chat Model은 혼자 못 돌고 반드시 체인에 꽂혀 있어야 동작. 캔버스에서 한 쌍 연결해 "모델 단독 실행 불가" 1회 강조.

    🖥️ ★self-host는 공짜가 아니다

    내 노트북에 띄웠다는 건 운영 책임도 내 것

    "로컬 체험"과 "사내 24시간 운영"은 다릅니다. self-host의 숨은 비용 세 가지를 기억하세요.

    ℹ️

    오늘 쓴 npx n8n은 내 노트북에서 빠르게 체험·실습하려는 용도입니다(켜는 동안만 동작·내 PC 한정). 사내에서 24시간 돌리는 "운영"은 다른 일이에요 — 이때는 Docker·서버·백업·보안이 필요하고, 그건 사내 IT와 함께 설계할 영역입니다. 즉 self-host = 빠른 로컬 시작이지, 그 자체로 "운영 준비 완료"는 아닙니다.

    🔄
    업데이트
    n8n은 자주(거의 매주) 새 버전이 나옵니다. 이미지를 직접 pull해 올려야 보안·기능이 따라옵니다.
    💾
    백업
    ~/.n8n 폴더(database.sqlite+config)를 외부로 복사해 둬야 합니다. 이 폴더가 날아가면 워크플로·자격증명이 전부 사라집니다.
    🔒
    보안
    사내 운영이라면 HTTPS·계정 관리·API 키/자격증명 보호를 직접 책임집니다. 외부 노출이 필요하면 사내 IT와 함께 설계하세요(이때는 Docker도 한 방법). 로컬 체험과 사내 24시간 운영은 다릅니다.
    🔒

    보안이 걱정되면 — 버전 고정 + 운영 보안 (소스 zip 아님)
    ① 버전 고정: 매번 최신을 받지 말고 검증된 같은 버전을 고정하세요 — npx n8n@1.xx.x(번호는 당일 확인). Docker로 운영한다면 이미지 태그를 n8nio/n8n:1.xx.x로 고정합니다.
    ② "소스 zip으로 설치가 더 안전"은 오해: npx든 소스 빌드든 결국 같은 npm 의존성을 받아옵니다 — 소스는 빌드만 복잡해질 뿐 더 안전하지 않아요. 보안의 답은 버전 고정입니다.
    ③ 운영 보안: 네트워크는 HTTPS·계정 인증으로 막고, 자격증명 암호화 키(N8N_ENCRYPTION_KEY)는 따로 안전하게 보관하며, 정기 백업을 돌립니다 — 상세 절차는 47-selfhost-보안-가이드.md.
    혼자 로컬 체험은 안전하지만, 사내 24시간 운영은 사내 IT와 함께 설계하세요.

    self-host의 진짜 메시지 — 띄우는 건 쉽지만 운영은 책임. ①업데이트(npx 실습자=`npx --yes n8n@latest`, global 설치자=`npm update -g n8n`) ②백업(~/.n8n 폴더 복사 — database.sqlite+config, 날아가면 전부 소실) ③보안(HTTPS·계정·자격증명). 로컬 체험과 사내 24시간 운영은 다르고, 후자는 사내 IT와.
