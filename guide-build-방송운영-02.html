02. 방송 결과 리포트 자동 초안

방송 종료 후 매출·주문·콜·반품 지표를 모아 Claude가 '잘된 점/아쉬운 점/개선안' 리포트 초안을 써서 MD에게 보내고 아카이브합니다.

받는 사람: MD · 분류: 방송 운영 · 데이터 파일: 방송결과.csv 헤더: 방송명 · 목표매출 · 매출 · 주문건수 · 콜인입 · 콜포기율 · 반품건수 — ~/.n8n-files에 넣기

처음 만드는 필드 종류(노드 추가·연결·표현식 토글·크리덴셜)는 공통 조작법을 먼저 보세요.

🤖 경로 A — Claude Code에게 시키기 (메타프롬프트)

이 강의의 방식대로, 아래 프롬프트를 Claude Code에 그대로 붙여넣으면 이 워크플로 JSON을 만들어줍니다(n8n-MCP 연결 시 더 정확). 받은 JSON을 ⋮ → Import from File로 불러온 뒤 노드별 Test step으로 검증하세요 — AI 초안은 가설, 진실은 에디터 실행 결과입니다.

n8n 워크플로 JSON을 만들어줘: "방송 결과 리포트 자동 초안" 자동화야. (데이터는 CSV 파일 기준)

[목표] 방송 종료 후 지표를 모아 Claude가 [요약][잘된 점][아쉬운 점][다음 방송 개선안] 리포트 초안을 써서 MD 메일 + 날짜별 CSV 아카이브.

[노드 체인 — 8개]
1. Schedule Trigger — 매일 23:30
2. Read/Write Files from Disk — 읽기: YOUR_DATA_DIR/방송결과.csv (헤더: 방송명·목표매출·매출·주문건수·콜인입·콜포기율·반품건수)
3. Extract from File — CSV 파싱. ★노드 이름 '방송결과 지표 읽기'
4. Code — 지표 정리: 숫자화 후 달성률=round(매출/목표×100), 반품률=round(반품/주문×100),
   "방송/목표매출/매출(달성률)/주문/콜인입/콜포기율/반품(반품률)" 멀티라인 metrics 텍스트 생성.
5. HTTP Request(POST) — Claude에게 "MD가 팀에 공유할 방송 결과 리포트 초안을
   [요약][잘된 점][아쉬운 점][다음 방송 개선안] 4개 소제목으로, 사실 기반으로 간결하게" 요청. metrics 포함.
6. Gmail — MD에게: 제목 "[방송리포트] {방송명} (달성률 {달성률}%)", 본문 = metrics + 구분선 + Claude 리포트.
7. Convert to File — CSV 변환 (노드 이름 '방송리포트로그 CSV 변환')
8. Read/Write Files from Disk — 쓰기: YOUR_DATA_DIR/방송리포트로그_{{ $now.format('yyyy-LL-dd_HHmm') }}.csv (노드 이름 '리포트 아카이브')
★연결 주의: 5번(Claude) 출력이 6번(Gmail)·7번(Convert) **둘 다**로 나가는 fan-out.

[공통 규칙 — 그대로 지켜줘]
- n8n-MCP가 연결돼 있으면 각 노드의 정확한 파라미터를 조회해서 만들고, 없으면 표준 노드 구조로.
- 데이터는 CSV 파일 기준: 경로는 YOUR_DATA_DIR/… 플레이스홀더로.
  (self-host n8n은 ~/.n8n-files 안의 파일만 접근 가능 — 사용자가 절대경로로 교체할 것)
- Claude 호출은 HTTP Request 노드로: POST https://api.anthropic.com/v1/messages,
  인증은 Header Auth 크리덴셜(이름 x-api-key), 추가 헤더 anthropic-version: 2023-06-01,
  모델 claude-sonnet-5, 응답 본문은 content[0].text 로 파싱.
- 수신자 이메일은 YOUR_...@example.com 플레이스홀더로.
- connections의 타입은 전부 "main". IF 노드는 true 출력만 다음 노드로.
- 완성되면 워크플로 JSON을 파일로 저장해줘 — 내가 n8n에서 ⋮ → Import from File 로 불러올게.
- import 후엔 노드별 Test step으로 하나씩 검증할 거야(통째로 맞다고 가정하지 말 것).

🗂 이 프롬프트는 기본(파일 버전) 기준입니다. 팀 공유용 구글시트 버전(보조)이 필요하면 파일 버전 가이드 §4의 시트 변환 단락을 덧붙이세요.

🔧 경로 B — 손으로 직접 만들기 (스텝바이스텝)

노드가 왜 이 순서로 놓이는지 이해하려면 이 경로로. 아래 Step은 기본(파일 버전) 기준입니다 — 구글시트 버전(보조)은 파일 노드 2단 자리에 Google Sheets 노드 1개가 들어갑니다: 차이 보기

노드 순서 (총 8개): 방송 종료 후 23:30 → 방송결과 파일 읽기 → 방송결과 지표 읽기 → 지표 정리 → Claude 리포트 작성 → MD 리포트 초안 → 방송리포트로그 CSV 변환 → 리포트 아카이브

Step 1 — 방송 종료 후 23:30 추가

  • 검색어: Schedule Trigger
  • 속성 설정: Trigger Interval → Days 선택 → Hour = 23, Minute = 30 (n8n 인스턴스 타임존이 이미 Asia/Seoul이면 이게 곧 한국시간입니다 — 1일차 설치 때 GENERIC_TIMEZONE=Asia/Seoul로 띄운 그 설정)
  • 연결: 이 노드가 시작점입니다(입력 연결 없음).

Step 2 — 방송결과 파일 읽기 추가

  • 검색어: Read/Write Files from Disk
  • 속성 설정:
    • Operation = Read File(s) From Disk (기본값)
    • File(s) Selector = YOUR_DATA_DIR/방송결과.csv → YOUR_DATA_DIR를 본인 ~/.n8n-files 절대경로로 교체
  • 연결: 이전 노드 출력(●) → 이 노드 입력(●)
  • 테스트 포인트: Test step 출력에 파일이 바이너리(data)로 잡히는지 확인. 파일이 없거나 허용 폴더 밖이면 여기서 에러.

Step 3 — 방송결과 지표 읽기 추가

  • 검색어: Extract from File
  • 속성 설정: Operation = Extract From CSV → Options → Exclude Byte Order Mark (BOM) 켜기(엑셀이 저장한 CSV 대응 · 엑셀 파일 자체면 Extract From XLSX)
  • 연결: 이전 노드 출력(●) → 이 노드 입력(●)
  • 테스트 포인트: Test step에서 CSV 각 행이 JSON 아이템으로 나오는지(헤더 = 필드명) 확인 — 여기서부터는 시트 버전과 데이터 모양이 완전히 같습니다.

Step 4 — 지표 정리 추가

  • 검색어: Code
  • 속성 설정: Mode = Run Once for All Items (기본값, 바꾸지 않음) → JavaScript 편집창에 아래 코드를 그대로 붙여넣기:
const r=$json;
const num=v=>Number(String(v||0).replace(/[,\s]/g,''))||0;
const 목표=num(r['목표매출']),매출=num(r['매출']);
const 달성률=목표>0?Math.round(매출/목표*100):0;
const 주문=num(r['주문건수']),반품=num(r['반품건수']);
const 반품률=주문>0?Math.round(반품/주문*100):0;
const metrics=`방송: ${r['방송명']||'-'}\n목표매출 ${목표.toLocaleString()} / 매출 ${매출.toLocaleString()} (달성률 ${달성률}%)\n주문 ${주문}건 / 콜인입 ${r['콜인입']||'-'} / 콜포기율 ${r['콜포기율']||'-'} / 반품 ${반품}건(반품률 ${반품률}%)`;
return [{json:{방송명:r['방송명'],달성률,metrics}}];
  • 연결: 이전 노드 출력(●) → 이 노드 입력(●)
  • 테스트 포인트: Test step 눌러서 출력 JSON에 기대한 필드(위 코드의 return에 있는 키들)가 정확히 나오는지 확인하세요. 여기서 필드명 오타가 나면 다음 노드부터 전부 빈 값이 됩니다.

Step 5 — Claude 리포트 작성 추가

  • 검색어: HTTP Request
  • 속성 설정:
    • Method = POST
    • URL = https://api.anthropic.com/v1/messages
    • Authentication = Generic Credential Type → Generic Auth Type = Header Auth → Credential = 공통 조작법에서 만든 x-api-key 크리덴셜 선택
    • Send Headers = On → Add Header 2번:
      • anthropic-version = 2023-06-01
      • content-type = application/json
    • Send Body = On → Body Content Type = JSON → Specify Body = Using JSON → 필드의 표현식 토글(=) 켜고 아래를 그대로 붙여넣기:
{{ JSON.stringify({ model: 'claude-sonnet-5', max_tokens: 800, thinking: { type: 'disabled' }, messages: [{ role: 'user', content: '다음은 오늘 홈쇼핑 방송 결과 지표다. MD가 팀에 공유할 방송 결과 리포트 초안을 아래 4개 소제목으로 한국어로 작성해줘: [요약] [잘된 점] [아쉬운 점] [다음 방송 개선안]. 사실 기반으로 간결하게.\n' + $json['metrics'] }] }) }}
  • 연결: 이전 노드 출력(●) → 이 노드 입력(●)
  • 테스트 포인트: Test step에서 content[0].text에 Claude의 응답 문장이 들어있는지 확인. invalid x-api-key 에러면 크리덴셜 값을 다시 확인하세요.

Step 6 — MD 리포트 초안 추가

  • 검색어: Gmail
  • 속성 설정:
    • Credential: 공통 조작법에서 만든 Gmail 계정 선택
    • Operation = Send (기본값)
    • To: 표현식 토글 끄고 → YOUR_MD@example.com (본인 이메일로 교체해서 테스트)
    • Subject: 표현식 토글(=) 켜고 → [방송리포트] {{ $('지표 정리').item.json['방송명'] }} (달성률 {{ $('지표 정리').item.json['달성률'] }}%)
    • Email Type = Text
    • Message: 표현식 토글(=) 켜고 →
{{ $('지표 정리').item.json['metrics'] }}

─────────────
{{ $json.content[0].text }}
  • 연결: 이전 노드 출력(●) → 이 노드 입력(●)

Step 7 — 방송리포트로그 CSV 변환 추가

  • 검색어: Convert to File
  • 속성 설정: Operation = Convert to CSV (엑셀로 저장하려면 Convert to XLSX)
  • 연결: 이전 노드 출력(●) → 이 노드 입력(●)

Step 8 — 리포트 아카이브 추가

  • 검색어: Read/Write Files from Disk
  • 속성 설정:
    • Operation = Write File to Disk
    • File Path and Name: 표현식 토글(=) 켜고 → YOUR_DATA_DIR/방송리포트로그_{{ $now.format('yyyy-LL-dd_HHmm') }}.csv
    • Input Binary Field = data (기본값)
    • YOUR_DATA_DIR는 본인 ~/.n8n-files 절대경로로 교체 (macOS /Users/계정/.n8n-files · 윈도우 C:\Users\계정\.n8n-files)
  • 연결: 이전 노드 출력(●) → 이 노드 입력(●)
  • 테스트 포인트: 실행 후 폴더에 날짜가 붙은 파일이 생겼는지 확인. Access to the file is not allowed 에러면 경로가 ~/.n8n-files 밖입니다(에러 전문을 Claude Code에 붙여넣으면 해결).

⚠️ 가지 나뉘는 지점(fan-out):

  • Claude 리포트 작성의 출력(●)에서 드래그를 두 번 해서 MD 리포트 초안 · 방송리포트로그 CSV 변환 둘 다에 연결하세요(같은 출력에서 두 갈래로 나갑니다 — 다중출력).

✅ 완성 후 테스트: 트리거 노드에서 Test step(또는 Execute Workflow) → 마지막 노드까지 전부 초록불이 뜨는지 확인. 안 뜨면 그 노드를 더블클릭해 에러 메시지를 읽고, 표현식 토글(=)이 켜져 있는지부터 확인하세요.
