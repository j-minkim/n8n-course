self-host n8n 보안 · 버전 고정 가이드

self-host는 "내 서버"인 만큼 보안·버전 관리도 내 책임입니다. 이 강의는 npx로 쉽게 시작하되, "사내 24시간 운영"으로 가면 아래를 챙깁니다. 비개발자는 ★ 표시만 알면 충분하고, 나머지는 사내 IT와 함께.

1. ★버전 고정 (재현성 · 공급망)

  • 최신 배포 정보는 실행 없는 npm view n8n version으로 조회합니다(정보용·변동 가능). 강의 재현은 2026-07-15 검증·실제 import 기준 2.26.8로 고정합니다:
    # macOS / Linux
GENERIC_TIMEZONE=Asia/Seoul npx n8n@2.26.8

    # Windows PowerShell
$env:GENERIC_TIMEZONE='Asia/Seoul'; npx n8n@2.26.8
  • 팀·강의에선 버전 1개를 지정해 전원 동일하게.
  • Docker(사내 서버)면 이미지 tag 고정: docker.n8n.io/n8nio/n8n:2.26.8
  • ⚠️ 강의 전 npm view n8n version과 공식 릴리스 노트로 최신 후보를 확인하되, 후보 버전은 별도 환경에서 검증하기 전 실습·운영에 적용하지 않습니다.

2. ★공급망(의존성) 보안 — "소스 zip이 더 안전"은 오해

  • npx든 소스 빌드든 결국 같은 npm 레지스트리에서 의존성을 받습니다. 소스 zip으로 설치해도 공급망 신뢰는 동일하고 빌드만 복잡해져요. → 버전 고정 + lockfile이 1차 방어.
  • 사내 강화: 사내 npm 미러/프록시(Verdaccio·Artifactory 등)로 외부 패키지를 사내에서 검증·캐시.

3. self-host 운영 보안 (사내 서버 전환 시)

  • 네트워크: 로컬 체험은 localhost(외부 노출 없음). 사내 노출 시 HTTPS(역방향 프록시)·접근 인증·방화벽 필수.
  • 인증: Owner 계정 강력한 비밀번호. (가능하면 SSO·2FA)
  • ★자격증명 암호화 키: N8N_ENCRYPTION_KEY는 실행 시 지정할 수 있는 환경변수 override이고, ~/.n8n/config에는 encryptionKey 값이 저장됩니다. 같은 키가 있어야 저장된 자격증명을 복호화할 수 있으므로 유출 금지, 백업은 데이터와 분리 보관합니다.
  • 업데이트: npm view n8n version으로 후보를 조회만 하고, 별도 환경에서 테스트한 후 npx 고정 번호 또는 Docker tag를 의도적으로 올립니다.
  • 백업: 로컬 실습은 n8n을 정상 종료한 뒤 ~/.n8n 전체(database.sqlite+config 등)를 복사하고 복원 시험을 한다. 운영환경은 사용하는 DB별 일관된 스냅샷·백업 절차를 사내 IT와 적용한다. 암호화 키는 데이터와 분리 보관하되 복원에 필요한 세트로 관리한다.
  • 모니터링: 접근·실행 로그 점검.
  • 웹훅: 강의 Webhook 템플릿 2종은 Header Auth가 설정되어 있습니다. 외부 노출 전에는 키를 본인 값으로 교체하고 허용 메서드·요청 크기·필수 필드도 제한합니다. 인증을 제거한 채 인터넷에 공개하지 않습니다. 공식 점검: https://docs.n8n.io/hosting/securing/security-audit/

4. ★비개발자 한 줄 요약

  • 로컬 체험(npx)은 안전합니다. 사내 24시간 운영으로 가는 순간 위 항목은 사내 IT와 함께 — "내 노트북 체험"과 "운영"은 다른 일이에요.

흔한 오해

오해 사실
"소스 zip으로 설치하면 더 안전" ✗ 같은 npm 의존성·빌드만 복잡. 버전 고정이 답
"self-host면 무조건 안전" ✗ 네트워크 노출·인증·업데이트 방치하면 오히려 위험
"최신으로 자동 업데이트가 좋다" ✗ 운영은 버전 고정 후 테스트 → 의도적 업데이트

⚠️ 버전 번호·도구는 변동 → 강의 전 본인 환경에서 확인.
